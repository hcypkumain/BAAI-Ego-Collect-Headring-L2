# 通用部署：成功保存 N 条后轮换

## 默认规则

- 通用 EEG 图片任务和临时文字任务均按**成功保存**计数，默认 N=5，不等待主机质检回执。
- 原有显式 N、任务列表及作用域保留；没有策略时，只用该设备当前启用的图片列表初始化默认策略，不复制其他设备的列表 ID。EMG 未启用分组的流程不被暗改。
- 已存在的显式 `count_basis=qualified` 仅作为兼容选项保留；正常新配置一律为 `saved`，旧配置缺少此字段时也默认按保存计数。
- 未开录准备、取消、保存失败不凑数；重复保存确认不重复计数。质检状态独立，不将待检冒充合格。
- 修改 N 只影响下一块，当前块的 target_size 继续冻结。
- 临时文字任务保留独立 namespace、每任务 50 次的上限和按 N 次分组的轮换。累计保存记录持久化，不因主机回执未返回或 Pi 上的质检记录消失而倒退。

## 进度兼容与回滚

进度格式为 version 4，读取历史 version 1/2/3。保留可证明的旧关联；旧版没有记录、且本机无证据的历史保存不能凭空补计。

安装器在停止采集服务后备份各模态的策略、图片任务进度和已有/已登记的文字 namespace 进度。安装失败在同一采集锁内恢复。对已完成部署执行回滚时，如果进度已有变化，拒绝静默覆盖，必须先协调事务目录内的状态备份。不得只将旧 reader 覆盖到 version 4 进度上。

## 通用打包入口

继续使用 `deployment/phone-usb-entry/build_bundle.py`，原有 device/deps/APK/SDK 参数不变。

默认构建现在读取 `collector-release.json` 与 `collector-overrides/` 的冻结、逐文件校验输入，叠加在固定的 123 文件 Git 基线上；不会因工作目录未提交，就又打包成旧轮换逻辑。构建内容索引进入发布 ID 和安装包校验。缺少 release profile 或校验不符时直接拒绝，不回退旧版。

维护源码时，在整合工作树中执行：

```sh
python3 tools/update_saved_rotation_release.py
```

这会从审核后的源码更新冻结输入；验证后再建包。不要在含无关实验修改的工作树里更新冻结输入。

该通用入口与旧 monorepo 的 `fleet_maintenance --release stable`（历史236文件维护包）不是同一发布路径；旧入口保留作兼容，不应当作此新版完整升级入口。

## 范围

本次更新部署源码和工作站默认离线建包入口，不等于已给所有头环安装。17号仍需恢复网络、核对空闲与现有任务 namespace 后再部署。也没有自动提交或推送 Git 远端。
