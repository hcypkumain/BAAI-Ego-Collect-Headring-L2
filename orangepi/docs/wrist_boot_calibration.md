# 腕部相机：每次开机确认左右

适用版本：2026-10-09 开机标定更新。只处理两只 USB 腕部相机；头环的四路 ROS 相机继续使用原来的话题配置。

## 操作

网页现提供“看画面选择左右”和“遮挡镜头标定”两种方式。确认设备后先选择方式；没有网页时继续使用原遮挡流程。实体键盘在方式选择步骤按 A 进入遮挡标定，在人工选择步骤按 A 不会代替左右确认，按 B 可重新选择方式。

### 看画面选择左右

等待两路腕部实时画面出现，在其中一路下点击“这是左腕”或“这是右腕”，另一台自动分配相反侧。可轻微移动实际左腕来辨认来源。查看待确认结果后点击“确认左右”，成功后进入任务准备。选中按钮尚未保存左右，也不会开启录制。

仅当前预览来源和当前标定会话的选择有效。画面过期、缺一路、相机拔插或会话已变化时拒绝保存，请等待新画面并重新选择。切换方式会丢弃未确认的选择；切回遮挡方式从第一步开始。

### 遮挡镜头标定

1. 连接两只腕部相机，按实际需要佩戴到左腕和右腕。在光线充足的位置开始，两只镜头先保持无遮挡。
2. 听完设备清单，按 A 确认设备。第一次会进入本次开机的标定。
3. 听到提示后，两只镜头无遮挡，按 A 记录基准。
4. 只遮严左腕镜头，右腕保持无遮挡，按 A，保持到下一条提示。
5. 松开左腕镜头，只遮严右腕镜头，按 A，保持到下一条提示。
6. 松开两个镜头，按 A。听到“左右标定完成”后，本次开机后续各段直接使用该结果。

每一步都等语音说完再按键。标定时 A 检测当前一步，B 从头重来。光线太暗、两只同时遮挡、没有遮挡、连续两步遮同一只或帧数不足，都不会通过。遮挡需足够严密；画面变化不明确时调整后重试当前步骤。

完成标定后回到原采集流程：A 播报参考图像，A 开始；采集中 A 停止，随后 A 保存、B 重采。标定本身不会生成正式采集段。

## 哪些时候需要重做

| 情况 | 行为 |
| --- | --- |
| 一直开机，连续拍摄多段 | 沿用本次标定 |
| 一直开机，仅重启采集服务 | 沿用本次标定 |
| 头环/Pi 断电再开机，或操作系统重启 | 必须重新标定 |
| 相机拔插、扩展坞重连或腕部相机数量变化 | 旧结果失效，重新确认设备并标定 |
| 相机不拔线，直接互换左右佩戴位置 | 软件无法感知；设备确认或空闲状态按 C 重新标定 |

录制、准备和保存期间不会开启标定读取器，也不会修改当前录制的相机来源。按 C 应在设备确认或没有采集进程的空闲状态操作；也可结束采集后重启程序，再按 C。

## 实现与留存

`configs/devices.yaml` 的 `wrist_calibration.enabled: true` 开启此功能，当前只实现 `scope: boot`。USB 路径只定位视频源，左右由使用者的交替遮挡指定。当前两只相机序列号相同，无法靠序列号辨认佩戴侧。

结果原子写入 `runtime/wrist_calibration.json`，记录 Linux `boot_id`、本次相机连接标识、唯一标定编号、左右对应路径和标定方式。遮挡方式记录 `method: alternating_occlusion` 及四步亮度统计，人工方式记录 `method: manual_preview`。两种方式沿用相同的重启与拔插失效规则。连接标识包含视频节点生成时间，可识别同一插孔拔插后的变化。校验通过才使用左/右标签，否则显示“待本次开机标定”。文件丢失、损坏或标识不符时重新标定。

历史 `runtime/device_bindings.json` 仍辅助设备发现，但其中旧的左右确认不能绕过本次开机标定。每段的 `device_selection.json` 和 `meta.json` 中保存本段固定配置、`wrist_calibration_status` 和标定编号，供核对多段是否使用同一结果。

标定仅短暂读取图像亮度，不保存图像；实际视频继续由原有采集流程保存。语音凭据读取 `private/secrets.env`，不写进源代码、公开更新包或数据说明。

## 检查与回退

在 Pi 项目根目录运行 `bash orangepi/scripts/check.sh`。测试覆盖新开机失效、同次开机复用、拔插失效、遮挡错误拒绝、左右交换、主控按键和录制前校验；硬件遮挡验证需按上述步骤实际完成。

安装前源码归档在 SD 卡 `code-backups/before-boot-calibration-20261009-121309/source.tar`，附文件哈希验证。回退时先停止采集服务，再恢复受影响源码和配置；保留采集数据、运行环境及私有语音配置。
