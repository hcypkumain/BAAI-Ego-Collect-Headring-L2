# Orange Pi 网页采集台（2026-10-19）

## 设备规则

- 肌电先显示 A/B，由操作者分别握拳观察实时波形，手动指定实际左右并点击确认；序列号仅区分设备身份，不决定身体侧别。
- 腕部相机仍采用每次 Linux 开机标定。两只相机均为 `200901010001`，因此重插、换接口也会使旧标定失效。
- 同次开机且连接和佩戴位置不变时可连续录多段，也可重启采集服务而复用确认。肌电重新插拔、更换设备或新增第三套时旧确认失效。
- 在安全状态下可以从网页重新确认腕部或肌电左右。更换佩戴侧但没有拔线时，操作者仍须点击“重新指定肌电左右”。录制中不能更换绑定。

## 使用界面

网页由现有采集服务启动，端口 8765。Mac、手机和 Pi 处于同一局域网时可访问 `http://<Pi地址>:8765/`；Pi 本机使用 `http://127.0.0.1:8765/`。

默认访问需要 Pi 的访问码，保存在 `orangepi/runtime/dashboard_token`（权限 0600）。在 `configs/devices.yaml` 的 `web_ui` 中设置 `access_code_required: false`，页面、预览、回看和操作可直接访问，无需输入或携带访问码。设置为 `true` 或省略时恢复访问码要求。修改后重启采集服务生效。

界面包括当前流程步骤、可用操作按钮、实时相机预览、两套肌电各 8 通道信号包络、设备自检结果、USB 路径/接收器尾号、最近语音、录制时长、剩余存储、参考任务图片及本段路径。

“参考图像”是原始任务图库里的场景/操作参考图，如餐桌倒水，不是相机实时画面，也不等于已经开始录制。新版保留这套任务与数据命名规则。

流程是：确认设备 → 腕部左右确认（需要时）→ 肌电左右确认（需要时）→ 准备本段 → 设备就绪 → 开始录制 → 停止录制 → 回看（可选）→ 确认保存或重采 → 保存、检验 → 点击准备本段进入下一段。开始录制前保留倒计时。实时预览不会被计入录制数据。

## 录制回看与保存检验

停止后，Pi 会先完成视频文件收尾，通常几秒后“录制回看”就可以使用。选择左腕、右腕或一路头环相机，点击“回看所选录像”，用播放器暂停或拖动进度，再决定确认保存或重采。回看本身不会确认保存，也不会消费任务图像。

原始文件在录制时已经写到 Pi，页面“确认保存”表示确认保留本段并登记任务结果。重采仍保留旧文件、标注失败，方便后续排查。质量检验从停止后自动开始，可以与回看重叠。

回看直接按需读取 Pi 的 H.265 MP4，由浏览器解码；Pi 不额外压缩一份视频，正式文件的分辨率与帧率不变。浏览器需要支持 H.265。录制新一段时停止页面回看。

检验阶段显示正在检查的数据、已完成项数和用时。详细警告留在“质量检查详情”和原始报告，语音只播报简短摘要；登记完成后显示“本段已保存”，可继续回看或点击“准备本段”。质量错误仍阻止成功登记。

目前检验保持一次处理一路视频，使用两个 CPU 核心，仍采用原检查项目和阈值。当前约 19 秒、9 个采集设备的数据对照检验从约 74 秒缩短到约 37 秒，全部检查结果相同；实际速度会随片长、系统负载变化。

## 键盘

- 原 MINI_KEYBOARD：继续使用 A/B；专用小键盘独占输入，避免同时影响桌面。
- 任意接入 Pi 的普通 USB/蓝牙键盘：按 `Ctrl+Alt+A/B`。蓝牙键盘先在 Pi 系统设置中配对。程序依据按键能力发现键盘，不再依赖某个型号名称。键盘断开后采集服务继续运行并自动等待重连。
- 在网页里：直接点击按钮；页面聚焦且光标不在输入框或按钮时，可按 A/B 执行页面主/次操作。
- Mac 自己的键盘通过浏览器控制即可，不必再与 Pi 配对。
- Ctrl+Alt+C 为安全状态下重新标定腕部；Ctrl+Alt+D 重新打开肌电人工指定。肌电状态按 A 仅重复提示，按 B 重来；左右必须在网页明确选择并点击确认，键盘不能猜测或跳过。

## 性能与数据

实测机器为 Orange Pi CM5 Tablet / RK3588S，8 核，约 4 GB 内存。桌面当前输出 2560×1600；腕部相机输入 640×480、30 fps，头环相机图像 1920×1200，原录制参数保持不变。

预览使用内存目录 `/dev/shm`，相机发布约 3 fps（网页刷新约 2 fps）；肌电显示近 2 秒、20 ms 分窗的每通道最大/最小包络。显示值是有符号 24 位原始 ADC 计数，并非已换算电压。每个通道独立居中缩放，所以不能直接比较不同通道的绝对幅度。

准备和录制中从原有设备读取回调复制预览，网页服务不另开相机/串口。空闲和标定等待阶段由控制器管理一个预览进程；扫描、标定检测、正式采集之前先停止并等待它释放设备。预览写入由单独线程处理，文件写入失败不会停止正式录制。未收到新数据超过 3 秒就显示等待，避免把旧画面/波形当作实时信号。

仅提供局域网 HTTP 服务，不配置公网转发。访问码要求由 `web_ui.access_code_required` 控制；关闭时，能连接该端口的设备可以查看数据并操作采集台。两种设置下，网页命令都需要当前状态版本且只能执行当前步骤允许的动作，拒绝跨站操作，忙时拒绝第二条命令。正式采样率、视频格式等设备底层参数在这一版中仍由配置文件管理，界面暂不支持录制中调整它们。
